🚨 Severity: HIGH
💡 Vulnerability: CSV Injection (Formula Injection) vulnerability in ReservationExporter where fields starting with a carriage return character (`\r`) followed by formula trigger characters are not properly escaped, potentially leading to arbitrary code execution when opened in spreadsheet software like Excel.
🎯 Impact: An attacker could register a user with a malicious string (e.g., "\r=cmd|'/C calc'!A0") which gets exported by an admin to CSV. When the admin opens the CSV in a spreadsheet application, it executes the formula, leading to arbitrary code execution on the admin's machine.
🔧 Fix: Updated the `isSpreadsheetTrimmable` method in `ReservationExporter.java` to not trim carriage return characters (`\r`), meaning it will check `\r` and correctly apply the leading single quote protection for CSV export, and added the carriage return character to the formula trigger checks. Also added a unit test to verify the fix.
✅ Verification: Ensure the test `exportReservationsToCsv_fieldWithLeadingCarriageReturn_isEscaped` in `ReservationExporterTest.java` passes, verifying that fields starting with `\r` are prefixed with an apostrophe in the CSV output.
