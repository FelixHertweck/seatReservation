## 2026-09-05 - Fix CSV Injection vulnerability in ReservationExporter
**Vulnerability:** The custom CSV exporter (`ReservationExporter`) did not properly identify and escape the carriage return character (`\r`) as a potential prefix for a formula payload. Specifically, `isSpreadsheetTrimmable` only checked for characters considered whitespace by Java (like `\t` which was excluded, but `\r` is considered whitespace) but didn't exclude `\r` which could be used as a trigger. Or rather, it is a whitespace but the actual check for formula characters (`=`, `+`, `-`, `@`, `\t`) was missing `\r`. The CSV injection escaping logic skipped over spaces, but didn't correctly identify a leading `\r` as a formula trigger itself, which is a known CSV injection vector.
**Learning:** `\r` is a recognized formula trigger in spreadsheet applications, and must be treated as a trigger character just like `=`, `+`, `-`, `@`, and `\t`. Trimming whitespace is not enough; we must also verify that we aren't trimming away triggers, or we must explicitly check for `\r` as a trigger.
**Prevention:** When manually implementing CSV escaping to prevent formula injection, always include `\r` in the set of formula trigger characters and explicitly exclude it from leading whitespace trimming routines.
