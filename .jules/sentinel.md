## 2026-09-05 - CSV Injection via Unescaped Carriage Return
**Vulnerability:** A vulnerability in `ReservationExporter.java` allowed CSV injection payloads via a carriage return (`\r`) character. The application was trimming leading whitespace using `Character.isWhitespace(c)`, but specifically checking if the first non-whitespace character was a known formula trigger (like `=`, `+`, `-`, `@`, `\t`). However, the `isSpreadsheetTrimmable` method did not exclude `\r`, which is ignored by spreadsheet software (like Excel) when determining if a cell contains a formula.
**Learning:** Spreadsheet applications treat characters like Tab (`\t`) and Carriage Return (`\r`) as whitespace and ignore them when evaluating the start of a cell for formula triggers. A robust CSV injection defense must not only look for `=`, `+`, `-`, `@` but also properly handle `\t` and `\r`. If you trim these characters in your verification, you might miss the payload. Therefore, they should be treated as literal triggers themselves or excluded from whitespace stripping during the check.
**Prevention:** When implementing CSV injection protections (prepending `'`), do not rely solely on standard `Character.isWhitespace()` to strip leading spaces before checking for `=` or `+`. Ensure that `\t` and `\r` are explicitly handled as trigger characters, and exclude them from being "trimmed" during the safety check to correctly detect payloads like `\rcmd` or ` \n\tcmd`.
