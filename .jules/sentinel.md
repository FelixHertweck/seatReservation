## 2026-09-08 - Added carriage return (\r) to CSV injection protection
**Vulnerability:** The CSV exporter (`ReservationExporter`) protected against formula injection (CSV injection) by prefixing fields that start with formula characters (like `=`, `+`, `-`, `@`, `\t`) with a single quote. The `isSpreadsheetTrimmable` method correctly skipped most whitespace characters (space, newline) before checking for a formula trigger character. However, it did not skip or escape carriage returns (`\r`). Since Excel/LibreOffice trims carriage returns and evaluates the subsequent character, an attacker could bypass the protection using a payload like `\r=cmd`.
**Learning:** When sanitizing text for CSV injection, we must explicitly account for all whitespace characters that spreadsheet software trims. Using Java's `Character.isWhitespace()` isn't enough, as it includes things like `\r` and `\t` which are dangerous in spreadsheets and must be handled specially.
**Prevention:** Explicitly exclude `\r` (alongside `\t`) from the `isSpreadsheetTrimmable` check to ensure the payload trigger logic correctly evaluates or escapes the payload. Also, ensure tests don't use combined payloads like `\r=cmd` to test if `\r` was missed, but test `\rcmd` directly instead as explained in memory.
