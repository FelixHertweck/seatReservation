## 2024-05-24 - Avoid Memory-Intensive ListAll And Stream Operations
**Learning:** Using `repository.listAll()` to fetch large entity collections and filtering them in-memory via Java Streams is a significant performance bottleneck. This pattern consumes excessive memory for instantiation and creates CPU overhead for filtering. For instance, fetching all reservations and filtering them using `.stream().filter(r -> r.getStatus() == ReservationStatus.RESERVED).count()` iterates through every object loaded into memory, severely impacting performance for large tables.
**Action:** Always push counting, grouping, and filtering operations to the database using targeted HQL aggregation queries (e.g., `SELECT r.status, COUNT(r) FROM Reservation r GROUP BY r.status`). This prevents O(N) memory overhead and ensures faster execution. Only load specific entities into memory when modifying them or returning full object details is explicitly required.
