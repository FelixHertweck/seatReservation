## 2026-07-26 - Optimize In-Memory Filtering and Excessive Database Fetching
**Learning:** In Quarkus/Panache codebases, developers may unintentionally fetch large collections (e.g., all `EventUserAllowance` entities for a user, or all `Reservation` entities for an event) and filter them in memory using Streams. This leads to substantial O(N) fetching overhead and high memory consumption when targeted repository queries (like `findByUserAndEventId` or `findByEventIdAndSeatIds`) already exist and return exactly what's needed.
**Action:** Always inspect `.stream().filter(...)` patterns acting on repository results. Replace them with targeted database queries using existing Panache methods to push the filtering down to the database level, particularly for high-cardinality associations.
